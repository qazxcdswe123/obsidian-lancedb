# M1 本地关键词搜索验证

日期：2026-10-07。本报告记录 M1 完成时的验证结果与当时尚未实现的 M2 工作。当前 M0–M2 已按个人自用范围完成，最新状态见 [PLAN](PLAN.md) 和 [M2 验证报告](M2-VALIDATION.md)。全局安装方式、latest 决策与 M0 基础保持不变。

## 已交付

- 首次搜索懒启动外部 Node 子进程，恢复本设备缓存，异步核对 Markdown。加载插件本身不读取全库正文。
- 文件名标题、frontmatter 别名与标签、正文和非代码区内联标签提取；正文保留原文偏移，技术标识符使用独立辅助字段。
- ICU 中文/英文、大小写归一化、不做 stemming、不移除停用词；多词在同篇笔记内 AND，允许跨字段、跨段落。
- 双引号短语按源字段复核，支持跨行空白；不会拼接不同别名或标题/正文形成虚假短语。路径包含与标签精确过滤在候选选择阶段执行。
- 标题/别名精确匹配优先；候选分批读取，按笔记排序后展示前 50 个有效结果。显示总匹配数、片段，支持鼠标和方向键/Enter。
- 250 ms 保存去抖、32 篇批处理、串行写入；本地 ID 在文件和目录在线改名时保持。迟到读取/写入、删除与范围排除不能使旧搜索结果重新有效。
- 打开结果时检查笔记版本与编辑器正文哈希，选中当前原文；不能验证时提示重新搜索。
- 本地目录排除、手动重建、索引状态和环境检查。停用时关闭弹窗和进程；异常退出显示可恢复操作说明。

物理索引目前是单张 `notes_v1` 表；元数据列表存为字符串，SDK 从普通 JS 记录推导 schema，插件不直接依赖 Arrow。后台使用全局 SDK 的公开查询与异步批次接口。

## 环境与检查

| 项目 | 实测 |
| --- | --- |
| 平台 | macOS 15.7.3，Apple Silicon |
| 宿主 | Obsidian 1.13.7 / Electron 43.3.0 / 宿主 Node 24.18.1 |
| 搜索进程 | 外部 Node 24.20.0 |
| SDK | 全局安装的 LanceDB 0.39.0；这是本次观测值，不是版本限制 |
| 资源 | 解压完整平台 ZIP；测试目录含中文和空格，子进程 PATH 为空 |

执行 `npm run package:darwin-arm64`、`npm run verify:m0`、`npm run verify:m1`、`npm run lint` 和 `git diff --check`。lint 为零错误，保留公开 typings/API 门槛相关的设置搜索注册提示。没有提交 Git、运行远程 CI 或发布 release。

`verify:m1` 使用实际全局 SDK 和打包后的 IPC 子进程，覆盖：

- 中文、跨字段/跨段落 AND、跨行短语、短语字段边界、技术标识符与原文选区。
- 标题与别名精确排序；250 个干扰候选后的路径/标签命中；路径中的单引号；frontmatter/内联标签及代码区标签排除。
- 增量修改、删除、关库重开；第二个写入者被拒绝；正常停用后释放占用。
- 文件/目录改名保留 ID；读取期间删除；写入期间修改后恢复原文；范围扩大/缩小；手动重建。

真实 Obsidian 的临时 vault 中验证了搜索弹窗、鼠标定位、独立 Settings 窗口的 Enter 选择、排除项持久化、新增/保存/删除、目录改名、旧结果拒绝、重建和插件重启。强制 SIGKILL 搜索子进程后，Markdown 编辑与保存仍成功，界面显示进程退出提示，停用后弹窗数量为零。

## 测量结果

| 场景 | 结果 | 口径 |
| --- | --- | --- |
| Obsidian 初次搜索建库 | 约 185 ms | 6 个文件中索引 5 篇，1 篇被排除；仅小库 |
| Obsidian 重启插件后恢复 | 158 ms | 启动子进程、恢复索引、重新核对这 5 篇 |
| Obsidian 保存到可检索 | 280 / 275 / 272 ms | 三次小笔记保存；包含保存和插件去抖，事件后分别 279 / 274 / 271 ms |
| 安装包查询含 IPC | p95 2 ms | 259 篇合成笔记，40 次宽泛/过滤查询，不含 UI 150 ms 去抖 |
| 合成规模建库 | 11.02 秒 | 10,000 篇、102.48 MiB，包含提取、批量写入和索引整理；后端脚本，非 Obsidian 全流程 |
| 唯一词查询 | p95 0.84 ms | 后端，预热 2 次后 20 次测量 |
| 过滤到 100 篇的查询 | p95 6.33 ms | 后端，预热 2 次后 20 次测量 |
| 全库命中查询 | 单次 206.14 ms | 后端，命中 10,000 篇；尚未达到最终 100 ms 目标，也不是完整分布的 p95 |
| 数据库大小 | 约 100.14 MiB | 合成数据可高度压缩，不代表真实笔记比例 |
| 采样最大 RSS | 约 1,047 MiB | 基准 Node 进程，包含数据生成、SDK 与查询；不是 Obsidian 内存，也不是连续采样的真实峰值 |

复现规模检查：`npm run benchmark:keywords`。脚本构造临时数据并在结束时清理。没有用合成重复文本推断 Recall@10 或人工质量指标。

多窗口验证发现主窗口隐藏时浏览器定时器会把索引更新拖到约 2 秒；索引调度与 IPC 时限现使用 Node 定时器，弹窗去抖使用自身窗口定时器。复测结果如上。宽泛查询已使用字段投影和异步批次，避免一次性物化全部召回文本；进一步减少正文与片段工作留到 M2。

## 下一阶段的明确边界

- 当前缓存目录以主机名/平台哈希区分，未解决同名设备和跨设备同步；同步排除未做第二台设备验证。
- 正常单写入者锁已实现；崩溃遗留锁需要退出 Obsidian 后删除对应关键词缓存，尚无自动失效锁回收或有界进程恢复。
- 手动重建清空当前表，期间结果不完整；完成后切换索引代次、格式迁移与回退仍属于 M2。
- 长期维护目前使用固定变更数量阈值，需根据真实库与查询时延调优。全库宽泛查询及内存仍需优化。
- 最低宿主 1.11.4、其他系统/Node 安装组合、超长单篇、建库并发 UI 时延、真实 100 条查询和 OmniSearch 基线尚未验证。
- M3/M4 未实现，没有远程 embedding 配置或笔记外发。
